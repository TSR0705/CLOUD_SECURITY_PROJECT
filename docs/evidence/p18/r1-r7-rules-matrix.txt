1. CANONICAL RULE HIERARCHY & RECONCILED SPECIFICATION
--------------------------------------------------------------------------------
The Deterministic Decision Engine (packages/decision-engine) enforces rules R1–R7
in strict canonical precedence matching the authoritative Build Plan (Table 2.3),
ADR-0009, and Attack Taxonomy (T5). All decisions are pure mathematical functions:
  decide(policy, fileVersion, findings) -> DecisionResult

Canonical Rules Summary & Precedence:
  R1: Result Identity Verification (Mandatory Precondition / Safety Invariant)
      Asserts that finding scannedSha256, scannedStorageVersionId, and scannedSizeBytes
      strictly match the immutable file_versions ingest identity (bucket, key, version, sha, size).
      Any mismatch or malformed artifact identity strictly yields:
        -> BLOCK / RESULT_IDENTITY_MISMATCH (Rule R1)

  R2: Required Checks and Scanner Errors
      Verifies that all policy.requiredChecks are satisfied in findings.
      - Missing required check -> ERROR / REQUIRED_CHECK_MISSING (Rule R2)
      - Scanner daemon offline or stale signatures (> 7 days) -> ERROR / SCANNER_UNAVAILABLE (Rule R2)
      - Scanner timeout exceeded -> ERROR / SCAN_TIMEOUT (Rule R2)
      - Subprocess / parser failure -> ERROR / SCANNER_ERROR (Rule R2)

  R3: High- and Critical-Severity Failures
      Any finding with outcome FAIL and severity CRITICAL or HIGH produces:
        -> BLOCK (Rule R3)
      Primary reason is selected deterministically from highest-severity threat finding.
      Evaluates malware (MALWARE_DETECTED), active PDF content (ACTIVE_CONTENT_DETECTED),
      OOXML macros (OOXML_MACRO_DETECTED), embedded executables (EMBEDDED_EXECUTABLE_DETECTED),
      polyglots (POLYGLOT_DETECTED), and archive structural attacks (ARCHIVE_BOMB_DETECTED,
      ZIP_SLIP_DETECTED, OVERLAPPING_ENTRIES, UNSAFE_PATH, ENCRYPTED_ARCHIVE_FORBIDDEN).

      *** R2 / R3 PRECEDENCE EXCEPTION ***
      Threat detection (R3 BLOCK) strictly outranks scanner errors or missing checks (R2 ERROR).
      If an artifact contains confirmed malware or an archive bomb, and another check errors or
      is omitted, the decision is BLOCK (R3), NEVER ERROR (R2).

  R4: Medium-Severity and Suspicious Findings
      Any finding with outcome FAIL and severity MEDIUM, or outcome SUSPICIOUS, or WARN with
      severity MEDIUM (e.g. OOXML external relationships, duplicate archive entries, detector
      disagreements) follows policy.onSuspicious:
        -> QUARANTINE (default) or BLOCK (if configured) (Rule R4)
      Primary reason is the reasonCode of the applicable medium/suspicious finding.
      (If detector disagreement occurs and policy.disagreementAction === 'FLAG', terminal R4
      decision is skipped so the finding only contributes to risk score).

  R5: Required Content Disarm and Reconstruction (CDR)
      When policy.cdrRequired === true:
      Verifies that a sanitized CDR finding with outcome PASS is present.
      If absent or failed:
        -> QUARANTINE / CDR_REQUIRED_NOT_DONE (Rule R5)
      (Follows policy.onSuspicious if explicitly configured to BLOCK).

  R6: Manual-Review Risk Threshold
      When cumulative risk score of findings reaches or exceeds the review threshold:
      riskScore >= (policy.manualReview ?? policy.manualReviewThreshold ?? 50)
        -> QUARANTINE / RISK_THRESHOLD (Rule R6)
      (Follows policy.onSuspicious if explicitly configured to BLOCK).
      Boundary condition:
        riskScore == threshold     -> QUARANTINE / RISK_THRESHOLD (R6)
        riskScore == threshold - 1 -> ALLOW / ALL_CHECKS_PASSED (R7, below threshold)

  R7: Default Allow / Clean Verification
      If no higher-priority rule applies and all checks pass without error, threat,
      or unresolved suspicious findings:
        -> ALLOW / ALL_CHECKS_PASSED (Rule R7)
      Preserves computedRiskScore (non-zero if low-severity findings exist below threshold).
