2. NORMALIZATION PIPELINE & FAIL-CLOSED ARCHITECTURE
--------------------------------------------------------------------------------
1. Container CLI Normalization:
   - Command: qpdf --qdf --object-streams=disable <input.pdf> <normalized.pdf>
   - Uncompresses object streams and linearizes PDF structure into human-readable QDF.
   - Verified inside the production scanner container:
       $ docker build -t sug-scanner:test -f services/scanner/Dockerfile .
       $ docker run --rm sug-scanner:test qpdf --version
       qpdf version 11.3.0
   - Execution Timeout: 15,000 ms.
   - Max Buffer: 50 MB.

2. Strict Fail-Closed Guarantees:
   - Malformed PDF:
     If qpdf fails with exit code 2 (malformed / damaged trailer), normalization immediately
     aborts and returns:
       outcome: 'ERROR'
       reasonCode: 'PDF_MALFORMED'
   - Timeout:
     If qpdf hangs or exceeds timeout (15s):
       outcome: 'ERROR'
       reasonCode: 'PDF_NORMALIZATION_FAILED'
       evidence: { timedOut: true, status: 'NORMALIZATION_FAILED' }
   - Unexpected Crash / Execution Error:
     If qpdf exits with non-zero code other than 0 or 3 (warnings):
       outcome: 'ERROR'
       reasonCode: 'PDF_NORMALIZATION_FAILED'
   - Missing / Damaged End-of-File:
     In fallback / stream mode, missing `%%EOF` marker returns:
       outcome: 'ERROR'
       reasonCode: 'PDF_MALFORMED'
   - INVARIANT:
     Errors during normalization NEVER fall through or become clean results.

3. In-Process Stream Fallback:
   - FlateDecode stream extraction via zlib.inflateSync / zlib.inflateRawSync.
   - Per-stream expansion limit: 10 MB. Cumulative limit: 50 MB (guards against PDF Flate bombs).
   - Hex-encoded name normalization: resolves escapes such as:
     /#4a#61#76#61#53#63#72#69#70#74 -> /JavaScript
