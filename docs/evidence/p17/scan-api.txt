SECURE UPLOAD GATEWAY (SUG) — PHASE P17 SCAN FINDINGS API EVIDENCE
GET /api/v1/scans/:id SPECIFICATION, AUTHORIZATION & BOUNDARY VERIFICATION
================================================================================

1. ENDPOINT SPECIFICATION
--------------------------------------------------------------------------------
Path:        GET /api/v1/scans/:id
Description: Retrieves scan job execution status and deterministic security findings.
Auth:        Bearer <sug_api_key> (P6 API Key) OR Bearer <user_jwt> (P7 Dashboard JWT)
OpenAPI:     Generated and validated in docs/openapi.json under "Scans" tag.

2. SECURITY & AUTHORIZATION INVARIANTS
--------------------------------------------------------------------------------
1. Authentication:
   - Unauthenticated requests return HTTP 401 with RFC 7807/9457 Problem Details.
   - Rejects invalid, malformed, or revoked API keys and expired JWTs.
2. Parameter Validation:
   - Non-UUID scan IDs return HTTP 400 with `urn:sug:error:validation`.
3. Existence:
   - Unknown scan jobs return HTTP 404 with `urn:sug:error:not-found`.
4. Tenant Application Isolation:
   - If authenticated via API Key: the scan job's associated file must belong to
     the caller's `application_id`.
   - Access attempts across tenant applications return HTTP 403 Forbidden with
     `urn:sug:error:forbidden`.
5. Empty Findings Handling:
   - If a scan job is queued, running, or has no findings recorded yet, the endpoint
     returns HTTP 200 OK with `findings: []`.
6. Deterministic Finding Order:
   - All findings returned in the `findings` array are deterministically sorted
     by `check_id ASC`.
7. Safe Response Fields & Secret Sanitization:
   - Serialized strictly against Fastify OpenAPI response schema.
   - Any sensitive internal database columns, pepper, passwords, raw hashes, or
     file paths are stripped and never leaked in API responses.

4. DATABASE LEAST-PRIVILEGE ROLE ENFORCEMENT
--------------------------------------------------------------------------------
Role `sug_scanner`:
  - Granted: SELECT, INSERT on `scan_results`; SELECT, UPDATE on `scan_jobs`; SELECT on `file_versions`.
  - Prohibited: UPDATE and DELETE on `scan_results` (enforced via trigger and role grants).
  - Verified: scanner inserts findings successfully and queries existing findings for idempotency.
Role `sug_api`:
  - Granted: SELECT on `scan_results`, `scan_jobs`, `file_versions`.
  - Prohibited: INSERT, UPDATE, and DELETE on `scan_results`.
  - Verified: API queries findings for tenant-scoped responses; direct INSERT attempts fail with
    PostgreSQL error: permission denied for table scan_results.
