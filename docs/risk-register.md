# Project Risk Register

This register identifies, assesses, and tracks mitigation strategies for all technical, operational, and research risks associated with the Secure Upload Gateway project.

### Likelihood / Impact Scale
- **Low (L)**: Unlikely to occur; minimal operational disruption.
- **Medium (M)**: Moderate likelihood; noticeable impact on schedule or testing fidelity.
- **High (H)**: High likelihood or severe impact (e.g., security breach, unbudgeted financial loss, failed research hypothesis).

---

| **R-01** | Local S3 emulator (LocalStack) diverges from AWS S3 on version IDs, conditional `If-None-Match`, or checksums | M | H | Execute formal P2 storage assumption spike (`assumptions.test.ts`) before writing any storage integration code. | Automated test failures during P2 spike suite. | Pivot immediately to SeaweedFS 4.45 (supports S3 versioning & conditional writes) or develop against a real scratch AWS bucket. | **OPEN** (Closes at P2) |
| **R-02** | LocalStack Community does not enforce IAM policies locally, invalidating local privilege-separation testing | H | M | Implement DEC-003: enforce local privilege separation using distinct AWS access key credentials per service; defer real IAM negative testing to AWS. | Phase 2 verification checks on LocalStack IAM behaviour. | Run IAM blast-radius negative tests on AWS in Phase 29; optionally evaluate SeaweedFS identities if local enforcement is mandatory. | **OPEN** (Closes at P2) |

| **R-10** | Scanner container compromised by malicious or malformed file payload (e.g., zero-day parser vulnerability) | M | M | Run scanner container with read-only root filesystem, dropped capabilities (`cap_drop: ALL`), non-root user, and internal network isolation (zero internet egress).
